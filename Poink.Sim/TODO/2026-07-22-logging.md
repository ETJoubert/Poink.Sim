# Add Serilog logging (console + rolling file)

Status: Done

## Why

Poink.Sim has no `ILogger` usage anywhere today -- DB failures, load/save/
reset state changes, and even the RL training service's own startup
weight-restore failure (`RlTrainingService`'s constructor, which currently
swallows that exception in a bare `catch { }` with no message captured at
all) are all invisible outside of the UI-facing `Error`/`SaveStatus` strings.
This adds Serilog (console + a local rolling file), scoped to exactly what a
solo dev needs to see what the app is doing: DB calls and start/stop/load/
save/reset-type state changes -- not calculations, not simulation
tick-by-tick events, not training episode-by-episode events.

## Scope

### 1. Packages

Add `Serilog.AspNetCore` and `Serilog.Sinks.File` to `Poink.Sim.csproj`.
`Serilog.AspNetCore` already pulls in `Serilog.Sinks.Console` transitively --
no separate console-sink package needed.

### 2. Bootstrap (`Program.cs`)

`builder.Host.UseSerilog((context, configuration) => ...)` -- single-stage,
no early static `Log.Logger` bootstrap (this project has no layered config
to fail during host-building, so the dual-stage pattern's main benefit
doesn't apply here). Console sink + a `RollingInterval.Day` file sink at
`Poink.Sim/poink-sim-.log` (via `context.HostingEnvironment.ContentRootPath`),
`retainedFileCountLimit: 14` so it never grows unbounded, minimum level
Information with `Microsoft.AspNetCore` overridden to Warning (otherwise
Kestrel/routing/SignalR per-request noise floods a Blazor Server circuit).
Configured purely in code -- no `appsettings.json` (see "Non-goals").

### 3. `ILogger<T>` injection

Add an `ILogger<T>` constructor parameter to `TickRepository`, `BrainRepository`
(both currently have no explicit constructor), `SimulationEngine`, and
`RlTrainingService` (both already have one -- add a parameter to each). All
four are registered as singletons in `Program.cs` with no factory lambdas, so
DI resolves the new parameter automatically -- no `Program.cs` wiring needed.

### 4. Log statements

- **`TickRepository`**: Information on `ListTickTables`, `RefreshTickTableStats`,
  `CountTicks`. `ReadTicks` logs once inside its iterator body (on first
  enumeration, not per row) when the stream opens. `ReadWindow` gets **no**
  log -- it's called once per RL training episode, so logging it would be a
  training-episode firehose despite being a DB call; the one thing in that
  path worth surfacing (`RlTrainingService.RandomEpisodeWindow`'s 5-attempt
  fallback) gets a Warning instead. `EnsureRegistryTable` isn't logged --
  it's an idempotent no-op called on every one of the calls above already.
- **`BrainRepository`**: Information on `SaveBrain`, `ListBrains`,
  `DeleteBrain`, and `LoadWeights` (Warning if weights come back null).
  `EnsureDatabaseExists` logs only the rare `CREATE DATABASE` branch (Info);
  `EnsureTable` logs only the destructive old-shape `DROP TABLE` migration
  branch (Warning) -- neither logs its common no-op branch, since both run on
  every single public call.
- **`SimulationEngine`**: Information on `Play`/`Pause`/`Step` (success only),
  `Reset`, `Unload`, `Dispose`, and once in `FinishLoad` (shared by `TryLoad`/
  `TryLoadDummy`, tagged "historic" vs "dummy"). Error in `TryLoad`/
  `TryLoadDummy`'s existing catch blocks. `SetSpeed`/`SetMaxSpeed` stay
  unlogged (chatty UI state, not "important" state). The playback loop itself
  (`TimerCallback`/`AdvanceOneUnitLocked`/`DecideAndApply`/`PublishSnapshot`/
  `PublishProgress`) is never logged -- this is the tick-by-tick path the
  scope explicitly excludes.
- **`RlTrainingService`**: Information for "training started" / "training
  completed" around `TryStartTraining`'s loop (no per-episode line inside the
  loop itself), Error in its catch. `SaveBrain`/`RefreshSavedBrains`/
  `DeleteSavedBrain` only log their own catch blocks (Warning/Error) --
  `BrainRepository` already logs the underlying DB fact on success, so no
  redundant success line at this layer. `LoadSavedBrain` does log its own
  success line (Information) since it has name/architecture context
  `BrainRepository.LoadWeights` doesn't have, plus Warning on its two
  not-found branches and Error in its catch.

### 5. Fix the swallowed constructor `catch { }`

`RlTrainingService`'s constructor currently does `catch { }` around its
startup weight-restore, capturing nothing. Change to
`catch (Exception ex) { _logger.LogWarning(ex, "..."); }` -- behavior is
unchanged (still starts up untrained on failure, still doesn't rethrow),
this only adds visibility into a currently-invisible failure mode.

## Non-goals

- No changes to Poink.ML, Poink.Web, Poink.CLI, or any other project.
- No per-tick simulation playback logging, no per-episode training logging,
  no logging of calculations.
- No `appsettings.json` / `Serilog.Settings.Configuration` -- pure code
  config, consistent with this project not having any externalized config
  today.
- No centralized/remote log sink (Seq, ELK, Application Insights) -- console
  + local rolling file only.
- No change to the existing UI-facing `Error`/`SaveStatus` string fields --
  logging is additive alongside them, not a replacement.

## Verification

- Run the app; confirm Serilog-formatted lines appear in the console and
  `Poink.Sim/poink-sim-<date>.log` is created and grows.
- Load a simulation (both historic and dummy), Play/Step/Pause/Reset/Unload;
  confirm one log line per action and no per-tick spam even during a fast/Max
  playback run.
- Start a training run (e.g. 50 episodes); confirm exactly one "training
  started" and one "training completed" line, no per-episode lines, and (if
  a data gap is hit) at most an occasional `RandomEpisodeWindow` Warning.
- Save/Load/Delete a brain; confirm one log line per action.
- Stop Postgres, restart the app; confirm the constructor's weight-restore
  failure is now logged (Warning + exception) instead of silently swallowed,
  and the app still starts up untrained.
- Confirm `git status` doesn't show the new `.log` file(s) as untracked --
  already covered by the existing root `.gitignore`'s `*.log` rule.
